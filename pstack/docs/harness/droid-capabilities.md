# Droid capability and acceptance ledger

Read [DROID-ADAPTER.md](../../DROID-ADAPTER.md) before running active workflows. This ledger distinguishes advertised capability, adapted procedure and live acceptance. It does not authorize login, tests against integrations, installation changes or automation activation.

| Facility | Native procedure | Remaining acceptance boundary |
|---|---|---|
| Role models | Built-in worker/explorer plus user-configured native Subagents Light/Medium/Heavy routing; specialized original roles inherit. No plugin model pins or private role ledger. | Actual model/family and diverse-review gates need post-login evidence; settings may route all tiers to the same family. |
| Task fanout | Parent launches background tasks in one message, records IDs, receives automatic reports and advances phase barriers only after completion. | No nested Task, per-call model/read-only/environment fields or assumed Task fork. Conceptual coordinators plan/roll up; parent dispatches every leaf. |
| Isolation | Parent prepares exact-SHA worktrees, scopes paths and reserves shared resources. | Fresh-machine requirements need an authorized verified remote computer/environment or disposable container. Local worktree is a reduced guarantee, not a VM. |
| Plain checks | Native tuistory/agent-browser when exposed, with their current schemas. | Plain text/DOM snapshots do not replace formal same-surface QA, recordings or terminal byte/rendering evidence. |
| Formal controls | Official droid-control and full driver/capture/verify atoms; discover effective skill names. | Real app startup, action path, screenshot/recording and cleanup must actually succeed. Missing capability blocks the relevant gate. |
| Sessions | Discover metadata through native session-navigation or current droid search help, then read exact scoped exports after inspecting actual schema. | Search may span workspaces despite cwd. Without metadata-only scoping, do not inspect private corpus. Full eval/trail audits require actual tool events; only reflect permits its explicit digest fallback. |
| Loop | Authorized five-field UTC cron, explicit immediate-run setting, done predicate, replay-safe prompt, saved loop ID and list/readback; pause/cancel on hold/completion. | No assumed dynamic/event watcher equivalence or offline persistence. No polling for Task completion. |
| PR ownership | One writer per branch, parent-owned independent current-head verification and live forge readback. | Existing human approval, merge authorization, exact-SHA and independent-model gates remain mandatory. |
| Automation lifecycle | Discover current Create/List/Read/EditAutomation schema, selected Slack channels and remote target; review full draft, obtain approval/readiness, create safely disabled and read back exact ID. | Auth, integration grants, privacy, committed checkout, disabled boundary and actual trigger delivery remain unverified until separately approved. No automation is deployed on import. |
| Benny | Commit full `.factory/automations/benny/` pack; preserve local conflicts and user config outside it. Verify project-scoped dependencies and every setup gate. | Immutable source thread, trusted verdict, no-secret/no-Slack-write workers, compensation, control proof, bounded draft fix and thread-safety tests are retained. RunAutomation cannot test Slack message delivery. |
| Webhook UI | Native remote CreateAutomation receiver, protected server-only sender config, verified auth/payload contract, allowlisted JSON actions and harmless authorized delivery readback. | One-time native secret return is incompatible with chat relay under this workflow. Stop before creation unless a verified protected provisioning path exists. No invented URL/header/event schema. |
| Authoring | Native skill-creation wrapper or approved interactive wizard; full draft/feedback/iteration. | Workers cannot fabricate user approval. Keep manual-invocation metadata and original authoring gates. |

## Unrun integration checks

No authenticated Task/model execution, session transcript schema probe, webhook delivery, Slack posting, automation creation/edit/activation, PR write/merge, or live control QA is claimed by this prose adaptation. Verify these later against exact native targets with user authorization and independent readback. Historical upstream guides and pristine assets remain provenance, not Droid runtime instructions.
